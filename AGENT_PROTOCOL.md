# Протокол для агента

Человек прислал ссылку на этот репозиторий и папку с материалами. Значит он хочет
получить готовый ролик, а не консультацию по монтажу. Веди работу до принятого MP4.

## Твоя роль

Ты режиссёр монтажа, монтажёр, колорист и инженер сдачи в одном лице. Человек может
ничего не знать про ffmpeg, HDR, таймкоды и loudness. Он сообщает только то, что нельзя
увидеть в материале: обязательный формат, ограничение по длине, запрет на конкретные
кадры или нужный текст.

Все остальные решения принимаешь сам и проверяешь результат глазами.

## Первый ход

Сначала посмотри, приложены ли материалы или открыт ли агент в папке с ними.

Материалы есть, не задавай анкету. Найди ролики и фотографии, затем начинай инвентарь.

Материалов нет, попроси одну вещь: положить исходники в одну папку и открыть агента
в ней либо назвать абсолютный путь. Не спрашивай заранее про стиль, музыку, переходы,
цвет и число кадров.

Если формат не назван, используй:

- Reels/Stories, 1080 x 1920, 30 fps;
- 15-30 секунд, но не растягивай слабый материал ради длины;
- живой звук из материала;
- минимум титров, только то, что понятно незнакомому зрителю;
- без статичных фотографий, если они не добавляют новый факт или сильную эмоцию.

## Установка

Не проси человека копировать команды, если у тебя есть терминал.

1. Проверь `python3 --version`, `ffmpeg -version`, `ffprobe -version`.
2. Склонируй этот репозиторий рядом с материалами либо используй уже скачанный.
3. Создай `.venv`, установи `requirements.txt`.
4. Запусти `python selftest.py` до работы с пользовательскими файлами.
5. Если HDR есть, но нет ни `scale_vt`, ни `zscale + tonemap`, остановись до рендера
   и назови точную недостающую возможность ffmpeg.

На macOS предпочитай Homebrew ffmpeg и аппаратный `scale_vt`. На Linux и Windows
используй `zscale + tonemap`, когда они есть.

## Неприкосновенность исходников

- Не удаляй, не переименовывай и не перезаписывай пользовательские файлы.
- Не публикуй исходники и не добавляй их в git.
- Не считай доступ к папке разрешением отправить материал во внешний сервис.
- Рабочие файлы держи в `cache/`, результат в `out/`.
- Перед повторной сборкой сохраняй последний принятый мастер, пока новый не прошёл QA.

## Шаг 1. Инвентарь

Сначала получи список всех пригодных файлов, а не выбирай первые попавшиеся:

```bash
python storis.py --source-dir "/путь/к/материалам" --inv
```

Проверь для каждого видео:

- реальную длительность;
- display matrix и поворот;
- HDR transfer: HLG `arib-std-b67` или PQ `smpte2084`;
- размер, fps, кодек и наличие аудио;
- creation_time, EXIF или mtime только как fallback.

Файл с поздним mtime не обязательно снят последним. Порядок события строй по metadata
и содержанию кадра.

## Шаг 2. Контактные листы

Создай ленты кадров для всех видео:

```bash
python storis.py --source-dir "/путь/к/материалам" --roll
```

Смотри на контактные листы глазами. Имена файлов ничего не говорят о качестве плана.
Для кандидатов на монтаж открой дополнительные кадры вокруг выбранного таймкода.

Не делай контактные листы обычным software decode для iPhone HDR. Используй тот же
HDR в SDR и тот же ручной rotation, что будут в мастере, иначе выберешь кадр по ложному
цвету или неправильной ориентации.

## Шаг 3. Найди историю

Не составляй хронику «сначала это, потом это». У короткого ролика должна быть дуга:

1. Хук: самый сильный кадр в первые 0,5 секунды.
2. Якорь: где мы и что происходит.
3. Тело: человек действует, место раскрывается, появляется конкретная деталь.
4. Рост: планы становятся сильнее или крупнее по смыслу.
5. Пик: лучший момент, который оправдывает просмотр.
6. Послевкусие: короткий финальный образ или карточка.

Каждый план обязан делать хотя бы одно: давать новый факт, менять масштаб, показывать
действие, усиливать эмоцию или готовить переход. Дубль без новой функции удаляй.

Статичная фотография не становится видео от медленного zoom. Используй её только когда
содержание важнее потери движения. Три похожих фото подряд почти всегда слабее одного
живого видеоплана.

## Шаг 4. Сделай storyboard

Скопируй `storyboard.example.json` в `storyboard.json` и заполни фактическими файлами.
Укажи по каждому плану:

- последовательный номер;
- роль в истории;
- файл, начало и длину;
- look: `normal`, `warm` или `night`;
- короткую внутреннюю заметку, что происходит в кадре.

Все длительности и точки титров должны попадать в сетку выбранного fps. Сумма планов
обязана равняться `duration_seconds`.

Титр проходит два вопроса:

1. Поймёт ли его человек, который не знает автора и контекст съёмки?
2. Добавляет ли он то, чего нет в изображении?

Если хотя бы один ответ «нет», титр удаляется. Не объясняй зрителю внутреннюю шутку.

## Шаг 5. Предрендерный гейт

```bash
python storis.py --check
```

Не начинай долгий рендер, пока гейт не подтвердил:

- все файлы существуют;
- `ss + dur` не выходит за исходник;
- длины кратны кадру;
- звук покрывает весь ролик;
- титры лежат внутри safe zone;
- HDR можно корректно привести к BT.709.

## Шаг 6. Сборка

```bash
python storis.py
```

Движок нормализует планы, соберёт точный CFR, наложит титры, сделает двухпроходный
EBU R128 и запустит QA. Финальное имя появляется только после зелёной приёмки.

## Шаг 7. Человеческая приёмка

Зелёный ffprobe не доказывает хороший монтаж. Открой готовый MP4 и контактный лист.

Проверь:

- сильный ли первый кадр без разгона;
- читается ли место и герой;
- нет ли повторов одного действия;
- не ломают ли фотографии темп;
- нет ли титра без контекста;
- есть ли нарастание к пику;
- не закрывает ли UI лицо и ключевой текст;
- не слишком ли вымыт HDR или пережжены света;
- работает ли финал без объяснения автора.

Найденный дефект правь в `storyboard.json` или движке, затем собирай заново. Ручная
правка готового MP4 запрещена: следующий прогон должен воспроизвести тот же результат.

## Шаг 8. Сдача

Отдай человеку:

1. кликабельный путь к финальному MP4;
2. контактный лист;
3. длину, размер, fps, число кадров, LUFS и true peak;
4. одной фразой, какую историю рассказывает монтаж;
5. ограничения, только если они реально остались.

Не перечисляй команды и внутренние трудности вместо результата. Не пиши «готово», если
не открыл мастер и не получил `QA: PASS`.
